CS201 • MODULE 3 • OS OCT 2026 NOTES

Deadlock: A situation where set of processes are blocked because each process is holding a resource and waiting for another resource.

Four Coffman conditions must hold simultaneously: 1. Mutual Exclusion (non-shareable resource), 2. Hold and Wait (process holding R1 requests R2), 3. No Preemption (resources released voluntarily), 4. Circular Wait ($P_0 \rightarrow P_1 \rightarrow \dots \rightarrow P_0$).

If graph contains NO cycles $\implies$ no deadlock. If cycles exist in single-instance resources $\implies$ deadlock guaranteed.

RAW LECTURE TRANSCRIPT • MODULE 3

Sir started explaining chapter 3 on resource allocation. A deadlock condition occurs when multiple processes compete for a finite set of resources and none of them can proceed further because each is waiting for an event that only another waiting process can cause.

Then sir wrote on board four main conditions that must hold together: Mutual exclusion (only one process uses resource at a time), next is Hold and wait (holding at least one resource while waiting), then No preemption (resource cannot be forcibly taken), and finally Circular wait ($P_0 \to P_1 \dots \to P_0$).

Deadlock, in plain words

Likely 3-mark question

What it is

A permanent traffic jam of processes. Process A holds the printer and waits for the scanner; Process B holds the scanner and waits for the printer.

It needs all four

Mutual Exclusion + Hold & Wait + No Preemption + Circular Wait. If you break even one condition, deadlock is impossible.

How to write it in the exam

State definition $\to$ List 4 Coffman conditions $\to$ Draw simple 2-process RAG with cycle $\to$ Write 1 prevention strategy (e.g. Resource Ordering).
